# Mixed IQP-QCBM

Code and data for the article

> Youngseok Lee and Hyunwoo Kim, "Trainability and Mode Separation of Mixed IQP-QCBMs" (2026).
> An earlier version is available as arXiv:2607.27883.

A mixed IQP-QCBM is a weighted mixture of ancilla-free IQP circuits ("branches"). It generalizes the
ancilla-extended IQP quantum circuit Born machine. This repository holds what the article's figures and tables
are made from: the training and analysis code, the training and test splits, the per-run results, and the
figure scripts.

`REPRODUCE.md` maps every figure and table of the article to its script and input files, and says for each one
whether it can be rerun from this repository.

## Layout

| path | content |
|---|---|
| `manuscript/figures/` | the figure scripts `make_fig_*.py` and the figure PDFs of the article |
| `experiments/cosine_rerun/` | the training campaign of the article: code, cluster labels, per-run summaries, result tables |
| `experiments/<name>/` | the other experiments of the article, one folder each (see `REPRODUCE.md`) |
| `experiments/datasets/`, `experiments/data/` | the datasets and the 16-qubit training and test splits |
| `packages/iqp_fastcf/` | the closed-form trainer and evaluator used by the campaign |
| `legacy/experiments/randomized_iqp_mnist8x8/` | the mixed-IQP library of the earlier pipeline, with its tests and a modified copy of IQPopt |
| `legacy/experiments/paper_ours/` | results of the earlier pipeline that the article still uses, with the scripts and inputs that regenerate them (`REPRODUCE.md`, section "The earlier pipeline") |
| `environment.yml` | the conda environment |

## Quick start

Run these from the repository root.

```bash
conda env create -f environment.yml && conda activate iqpopt
pip install pytest

# regenerate a figure from the committed results (CPU, seconds)
(cd manuscript/figures && python make_fig_train_results.py)

# tests
(cd legacy/experiments/randomized_iqp_mnist8x8 && JAX_PLATFORMS=cpu python -m pytest -q tests)   # CPU, a few minutes
(cd packages/iqp_fastcf && python -m pytest -q tests)                                           # AMD GPU, see below
```

The figure scripts read the committed result files, so they need no GPU. Some of them also write a
`*_preview.png` next to the PDF, which git ignores here.

The reruns of the earlier pipeline (the numerical tests of the theorems and the RBM baseline) and of the
16-qubit product baselines also run on CPU (`REPRODUCE.md`).

Training and the evaluator of the campaign need more:

- `packages/iqp_fastcf` trains and evaluates on an AMD GPU through ROCm (`hipcc`). This version has no CPU
  path. The article's runs used one AMD Instinct MI300X.
- `environment.yml` installs the CPU build of jax. For `iqp_fastcf` and its tests, install the ROCm build named
  in the header of `environment.yml` instead. `iqp_fastcf` does not run on a CUDA build.
- Run the `iqp_fastcf` tests on an idle GPU. They compare the fast engine with a reference engine to 1e-8 and
  its memory modes with each other to 1e-10 and tighter, and they can fail while another job uses the same GPU.
  In the check for this release all eight passed on the idle GPU. With other jobs on the GPU,
  `test_trainable_weights` failed: two runs that should give the same losses agreed to 1.5e-12, and the test
  asks for 1e-12.
- Training on the GPU is therefore not bit-reproducible. `REPRODUCE.md`, section "Result of the check for this
  release", says how closely a retrained campaign and a rerun of every other experiment match the committed
  results, and lists the printed values of the article that such a rerun moves.
- `REPRODUCE.md`, section "Training", gives the commands that retrain the campaign.

## What is not in this repository

- **Trained parameters.** The angle files (`experiments/*/params/*.npz`, about 4 GB) are not included. They
  are regenerated by the training scripts and are available from the authors on request. `REPRODUCE.md` marks
  the scripts that need them. The only exceptions are `experiments/gd_escape/thstar_blobs.npy` and
  `experiments/gd_escape/thstar_ising.npy`, two local minima of the single-circuit loss (136 angles each) that
  the escape experiment uses as its reference (`REPRODUCE.md`, "Keep the two `thstar` files").
- **Four intermediate result files** of `experiments/gd_escape/results/` (6.5 MB each). `REPRODUCE.md` gives
  the command that regenerates them.
- **Most of the earlier pipeline.** The campaign of the article replaced an earlier training pipeline, from
  which the numerical tests of the theorems and the 16-qubit RBM baseline still come. Its training driver,
  its trained checkpoints and most of its configuration files are not included. What the scripts behind those
  two results need is included, and they run again from this repository (`REPRODUCE.md`, section "The earlier
  pipeline").

## Reading the code

- Docstrings, result notes and some `check` modes refer to internal run documents (`docs/...`) and to other
  files of the authors' working repository. These are not part of this repository.
- Figure numbers in docstrings may be those of earlier versions of the manuscript. `REPRODUCE.md` uses the
  LaTeX labels of the current one.
- Folder and docstring names with "referee" (for example `referee_2026_10`) refer to an internal review of the
  manuscript by the authors before submission, not to a journal's referees.
- "The arena" in `packages/iqp_fastcf/` is the authors' internal benchmark in which the engine was developed
  and checked. Its `judge.py` and the earlier training script `cf_multi.py`, which the package also mentions,
  are not part of this repository.
